# 프롬프트 매니저 개선 계획서 (사전 평가 기반)

## 1. 개요
본 계획서는 사전 평가 결과(`pre-review.md`) 중 단순 스크린샷 캡처 증빙을 제외하고, 논리적 설계 근거와 프로그램의 완성도를 높이기 위해 필요한 **코드 및 문서(README) 보완 사항**을 정리한 실행 계획입니다.

---

## 2. 코드 개선 (main.py 리팩토링)

### 2.1 프롬프트 중복 및 충돌 방지 로직 (항목 #6, #21)
- **현상**: 새로운 프롬프트 추가 시 제목이 완벽히 동일해도 그대로 저장됨.
- **개선 계획**: 
  - `add_prompt()` 실행 시 기존 프롬프트 목록을 순회하여 중복 제목이 있는지 검사하는 로직 추가.
  - 중복 발견 시 사용자에게 덮어쓸지 묻거나, 제목 뒤에 `_1` 같은 접미사를 자동으로 붙여 저장하도록 코드 개선.

### 2.2 주요 함수 입출력 명세(Docstring) 추가 (항목 #12)
- **현상**: 함수 분리는 잘 되어있으나 내부 설명 주석이 부족함.
- **개선 계획**: 
  - `add_prompt`, `show_list`, `search_prompt` 등 모든 주요 함수의 상단에 파이썬 표준 Docstring(`""" ... """`)을 활용하여 역할, 입력값, 출력 결과에 대한 1~2줄 요약 주석을 추가.

## 3. 문서 보강 (README.md 업데이트)

### 3.1 프로젝트 메타 정보 및 브랜치 전략 (항목 #3, #11, #19)
- **저장소 정보**: README 최상단에 실제 GitHub 퍼블릭 저장소 URL 추가.
- **브랜치 네이밍 및 병합 규칙**: 
  - 기능 개발은 `feature/기능명`, 버그 수정은 `fix/버그명` 형태를 따른다는 컨벤션 규칙 명시.
  - 병합 전 테스트를 거치고 `main`으로 Merge 한다는 규칙 문서화.

### 3.2 데이터 구조 및 영속화 설계 근거 (항목 #13, #16, #20)
- **List of Dict 구조 선택 이유**: 
  - 장점: 파이썬에서 다루기 가장 직관적이며 JSON 변환과 매핑이 1:1로 깔끔함.
  - 대안 비교: 클래스 기반 객체(Object) 지향이나 복잡한 관계형 DB를 쓰기에는 현재 요구사항 규모가 작아 오버엔지니어링이 될 수 있음을 서술.
- **JSON 영속화 선택 이유**: 
  - CSV 대비 계층적 데이터(예: 여러 줄의 content) 보관에 유리함.
  - 향후 데이터가 방대해질 경우 SQLite 등의 로컬 DB로 전환할 수 있다는 확장 방향성 제시.

### 3.3 프로그램 아키텍처 및 입력 규칙 (항목 #14, #17)
- **메인 루프 설계**: `while True` 무한 루프를 통해 사용자가 명시적으로 `0`을 입력해 종료(`break`)하기 전까지 인터랙션을 유지하는 구조의 이유와 안전성 명시.
- **입력 정규화 규칙**: 
  - 입력값의 공백 제거(`strip()`) 외에, 카테고리 입력 시 대소문자를 무시하도록 강제 변환(`lower()` 등) 처리하는 정책.
  - 제목 길이 제한 등 데이터 유효성 검사 기준 문서화.

### 3.4 검색 알고리즘 한계 및 개선 방향 (항목 #8, #18)
- **현상**: 단순 부분문자열 검색(`in` 연산자) 사용 중.
- **보완 내용**: 
  - 장점: 구현이 단순하고 리소스 소모가 적음.
  - 단점: 조사(은, 는, 이, 가)가 포함되거나 띄어쓰기가 다르면 검색에 실패함.
  - 향후 개선 방향: 정규표현식(Regex)을 통한 패턴 검색이나, 형태소 분석기(N-gram 토큰화 등)를 도입한 고도화 방안을 문서 말미에 한 문단으로 제안.

## 4. 향후 실행 순서
1. **문서(README.md) 업데이트**: 위 3장에 명시된 설계 근거와 규칙들을 섹션별로 분리하여 README에 깔끔하게 병합.
2. **코드(main.py) 리팩토링**: 중복 검사 로직과 주석을 코드에 반영하고 정상 작동 테스트 진행.
3. **최종 Git 커밋**: 개선된 사항들을 하나의 커밋 묶음으로 처리(`refactor: ...` 및 `docs: ...`)하여 변경 이력 보존.
