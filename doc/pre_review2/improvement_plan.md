# 프롬프트 매니저 2차 개선 계획서 (pre-review2.md 기반)

## 1. 개요
본 계획서는 2차 사전 평가 결과(`pre-review2.md`)에서 식별된 항목들 중 터미널 및 화면 스크린샷 캡처 증빙 요구사항을 제외하고, 코드 품질 및 문서(README)의 완성도를 한 단계 더 높이기 위한 실행 방안을 정리한 문서입니다.

---

## 2. 코드 개선 (main.py 기능 및 예외처리 강화)

### 2.1 UX 향상 및 예외 처리 고도화
- **비숫자 입력 및 범위 외 입력 안내 강화 (항목 #5)**: 
  - 현재 단순한 `except ValueError` 처리로 "숫자를 입력해야 합니다"만 출력하고 있으나, 사용자 안내를 강화하여 "오류: 리스트에 있는 유효한 메뉴 번호를 입력해 주세요."와 같이 메시지를 구체화할 예정입니다.
  - 범위를 벗어난 번호(`idx < 0` 또는 `idx >= len(prompts)`) 입력 시에도 원인을 명확히 안내합니다.
- **카테고리 목록 정렬 및 선택 편의성 제공 (항목 #7)**: 
  - `show_by_category()` 함수 호출 시 출력되는 카테고리 목록을 알파벳/가나다 순으로 정렬(Sorting)합니다.
  - 카테고리명을 직접 타이핑하는 방식 대신, `[1] 멀티미디어, [2] 업무자동화` 형태의 인덱스 번호를 부여해 숫자 입력만으로 카테고리를 조회할 수 있도록 인터페이스를 개선합니다.
- **즐겨찾기 토글 시 확인 옵션 (항목 #9)**: 
  - 즐겨찾기를 무심코 켜고 끄는 실수를 방지하기 위해, 상태 변경 직전 "해당 프롬프트의 즐겨찾기를 변경하시겠습니까? (y/n)" 형태의 재확인 프롬프트를 추가합니다.
- **강제 종료 시그널(SIGINT) 안전 처리 (항목 #17)**: 
  - 메인 루프를 `try-except KeyboardInterrupt:` 블록으로 감싸서 사용자가 `Ctrl+C`로 프로그램을 비정상 종료하더라도 "안전하게 프로그램을 종료합니다." 문구와 함께 `save_prompts()`가 호출되어 데이터 유실을 방지하도록 처리합니다.

## 3. 문서 보강 (README.md 업데이트)

### 3.1 아키텍처 및 자료구조의 한계/트레이드오프 분석
- **List of Dict의 단점 및 DB 대안 구체적 비교 (항목 #13, #16)**:
  - 현재 구조는 단순 검색(선형 탐색) 시 데이터가 수만 건 이상 증가하면 성능이 저하되는 단점이 있음을 명시합니다.
  - 대안으로 검색 속도(인덱싱)에 유리한 관계형 DB(SQLite)나 객체 무결성을 보장하는 클래스(Class) 기반 설계를 채택하지 않고 List of Dict를 유지한 이유(초기 개발 속도 및 직관성)를 구체적인 사례를 들어 비교 설명합니다.
- **동시성 및 백업(영속화) 세부 정책 (항목 #20)**:
  - `prompts.json`을 단일 파일로 덮어쓸 경우 여러 사용자가 동시 실행 시 발생하는 Race Condition 문제를 한계점으로 서술합니다.
  - 데이터 유실을 방지하기 위해 프로그램 실행 또는 종료 시 `prompts_backup.json`을 자동 생성하는 파일 백업 권장안을 추가합니다.

### 3.2 검색 기능 및 입력 정책 명세화
- **검색 정규화 및 토큰화/정규표현식(Regex) 계획 (항목 #8, #18)**:
  - 현재 부분문자열 검색의 띄어쓰기 불일치 문제를 해결하기 위해, 검색 키워드와 원본 텍스트의 공백을 모두 제거(`replace(" ", "")`)한 후 비교하는 정규화 단계를 문서화합니다.
  - 향후 파이썬의 `re` 모듈을 도입한 패턴 검색 고도화 계획을 서술합니다.
- **주요 함수 입출력(I/O) 명세표 작성 (항목 #12)**:
  - 현재 Docstring으로만 존재하는 각 함수의 역할과 책임을 표(Table) 포맷으로 정리하여, `add_prompt`, `show_list`, `search_prompt` 등의 입력 파라미터와 리턴 방식을 README에 추가합니다.
- **검증 및 충돌 정책 (항목 #14, #21)**:
  - 제목 최대 길이(50자), 필수값 검증, 카테고리 대문자 변환(Upper) 등 데이터 유효성 검증 규칙을 구체적으로 나열합니다.
  - 동명 제목 발생 시 시스템이 자동으로 `_1`, `_2` 접미사를 붙여 충돌을 회피하는 자동화 규칙을 명시합니다.

3. 작업 완료 후 단일 커밋(`feat & docs: ...`)으로 버전 트래킹.
