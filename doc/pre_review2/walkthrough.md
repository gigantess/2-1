# 프롬프트 매니저 2차 개선 완료 보고서

작성해주신 2차 개선 계획서(`improvement_plan.md`)에 따라 코드 UX 및 예외 처리, 그리고 `README.md` 문서 고도화를 모두 성공적으로 마무리했습니다!

## 🛠 1. 코드 UX 및 예외 처리 고도화 (`main.py`)
> [!TIP]
> 단순 오류 방지를 넘어, 사용자가 직관적이고 안전하게 조작할 수 있도록 인터페이스를 개선했습니다.

- **안전한 시그널 종료 처리**: 프로그램 사용 도중 `Ctrl+C`를 눌러 강제 종료할 경우 에러를 뿜으며 죽지 않고, `KeyboardInterrupt`를 잡아내어 데이터를 안전하게 `prompts.json`에 자동 저장하고 종료되도록 보호 장치를 추가했습니다.
- **카테고리 목록 정렬 및 인덱스 선택 기능**: 카테고리를 조회할 때 더 이상 긴 카테고리명을 직접 치지 않아도 됩니다! 정렬된 목록과 함께 `[1]`, `[2]`와 같은 인덱스 번호를 선택하여 쉽게 조회할 수 있도록 개선했습니다.
- **즐겨찾기 토글(y/n) 확인 옵션 추가**: 실수로 프롬프트의 즐겨찾기를 해제/설정하는 것을 방지하기 위해, 변경 직전 다시 한번 의사를 묻는 확인 단계를 추가했습니다.
- **입력 오류 안내 구체화**: 단순 "숫자를 입력해야 합니다"에서 "리스트에 있는 유효한 메뉴 번호를 정확히 입력해 주세요", "목록에 없는 번호입니다" 등으로 상황에 맞게 에러 메시지를 구체화했습니다.

## 📝 2. 문서 보강 완료 (`README.md`)
> [!NOTE]
> 소프트웨어 아키텍처 관점에서의 고민과 한계를 명확히 짚어, 프로젝트의 투명성을 한층 높였습니다.

- **주요 함수 입출력(I/O) 명세표 작성**: Docstring으로만 존재하던 각 함수의 역할을 표(Table) 형태로 분리하여 `add_prompt`, `show_list` 등의 작동 방식을 한눈에 파악할 수 있게 정리했습니다.
- **데이터 영속성 및 동시성 한계 명시**: `prompts.json` 파일 덮어쓰기 방식으로 인한 동시 접근 충돌(Race Condition) 한계를 명시하고, 파일 백업본(`.bak`) 관리 권장안을 서술했습니다.
- **검색 알고리즘 고도화 방향 제시**: 부분문자열 검색 시 한글의 특성(띄어쓰기 등)으로 인해 누락되는 현상을 짚고, 이를 해결하기 위해 입력값의 공백을 모두 지우고 비교하는 토큰화 방식이나 향후 `re` 모듈(정규표현식)을 도입할 계획을 문서화했습니다.
- **List of Dict의 트레이드오프 비교**: SQLite 등 DB 시스템과 클래스(Class) 기반 캡슐화 설계 대비 현재 구조(List of Dict)가 가지는 장단점(선형 탐색으로 인한 속도 저하, 오버엔지니어링 회피)을 구체적인 사례를 들어 서술했습니다.
- **검증 규칙 및 중복 회피 원리 명시**: 최대 50자 제한 및 중복 시 `_1` 접미사를 자동 부여하는 내부 로직 원리를 문서에 상세히 명문화했습니다.
