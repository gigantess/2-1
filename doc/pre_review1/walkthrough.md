# 프롬프트 매니저 개선 완료 보고서

사전 평가(`pre-review.md`) 기반으로 수립했던 개선 계획(`improvement_plan.md`)에 따라 코드 리팩토링과 문서 업데이트를 모두 완료했습니다! 주요 변경 사항은 아래와 같습니다.

## 🛠 코드 리팩토링 (`main.py`)
> [!TIP]
> 코드의 안정성과 가독성을 높이기 위해 입력값 유효성 검사 및 정규화 기능이 대폭 강화되었습니다.

- **프롬프트 추가(`add_prompt`) 검증 로직 도입**
  - **제목 중복 방지**: 사용자가 입력한 제목이 이미 목록에 존재할 경우, 자동으로 `_1`, `_2` 등의 접미사를 붙여 고유한 제목으로 저장되도록 개선했습니다.
  - **제목 길이 제한**: 제목이 50자를 초과할 수 없도록 제한을 두어 UI가 망가지는 현상을 방지했습니다.
  - **카테고리 정규화**: 카테고리 입력 시 앞뒤 공백을 제거하고 모두 **대문자로 변환(`upper()`)**하여, 대소문자 혼용에 의한 그룹화 오류를 해결했습니다.
- **주요 함수 Docstring(문서화 주석) 추가**
  - `add_prompt`, `show_list` 등 모든 15개의 주요 기능 함수 상단에 역할, 작동 방식, 예외 처리 등을 설명하는 파이썬 표준 Docstring을 명시하여 코드 가독성과 유지보수성을 극대화했습니다.

## 📝 문서 고도화 (`README.md`)
> [!NOTE]
> 프로젝트의 설계 근거(Why)를 명시하여 아키텍처 관점에서의 문서 품질을 한 단계 끌어올렸습니다.

- **설계 근거 명시 섹션 추가 (`4. 데이터 구조 및 설계 근거`)**
  - `list-of-dict` 구조를 채택한 이유와, `while True` 방식의 메인 루프 설계 의도를 구체적으로 서술했습니다.
  - JSON 형식의 영속화 선택 이유 및 향후 DB 마이그레이션 가능성을 제시했습니다.
- **검색 알고리즘 명세 및 개선 방향 (`3.3 아키텍처 및 설계 원칙`)**
  - 현재 도입된 `in` 연산자 기반의 부분문자열 검색 방식의 장점과 한계(조사/띄어쓰기 불일치)를 정리하고, 향후 N-gram 토큰화 및 정규표현식을 도입할 수 있는 방향성을 추가했습니다.
- **브랜치 네이밍 및 병합 컨벤션 명시 (`6. Git 8대 필수 명령어 및 브랜치 전략`)**
  - 기능 개발은 `feature/`, 버그 수정은 `fix/` 브랜치를 사용한다는 팀 협업용 브랜치 네이밍 규칙을 명문화했습니다.

이 개선 사항들은 `feat: Apply improvement plan` 이라는 Git 커밋 메시지와 함께 성공적으로 저장소에 반영되었습니다. 프로그램(`python main.py`)을 다시 실행하시어 중복 제목 방지 기능 등을 직접 확인해 보시기 바랍니다!
